# Economical model selection

Discover model controls from the current host's actual tool schema or documented capability. Some hosts support explicit model selection, some offer opaque routing, and some provide neither. A prose request to use a cheaper model does not establish that a switch occurred.

When selection is supported and authorized, choose based on task difficulty and failure cost. Extraction from clean inputs, straightforward transformations, and narrow inspections may suit a lower-cost model. Ambiguous architecture, difficult debugging, and integration decisions may justify a more capable model. These are starting hypotheses, not fixed assignments by brand or model name.

Use observed results to decide whether escalation is needed. A bounded unsuccessful attempt can be informative; repeated attempts with unchanged context and strategy rarely are. Provide the failed artifact and relevant evidence when escalating so the next attempt does not start over.

Consult current primary provider information before relying on changing model availability, limits, or pricing. If usage or pricing telemetry is missing, describe the routing decision without asserting a dollar or token saving. Compare total successful completion cost, including retries and review, rather than advertised unit price alone.
